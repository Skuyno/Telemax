## 2026-09-18 — Локальное окружение

Всё ниже — локальные файлы, в гит не попадают (`.env` и `docker-compose*.yml` в `.gitignore`).

- Созданы все `.env` по образцу `.env.example`: `deploy/.env`, `src/services/{identity,communication,api-gateway,ws-gateway}/.env`, `src/web/.env`.
  - `JWT_SECRET` одинаковый в `identity`, `api-gateway`, `ws-gateway` — иначе токен молча не проходит валидацию.
  - `POSTGRES_DB`: `telemax_identity` / `telemax_communication` — ровно те базы, что создаёт `deploy/initdb/01-databases.sql`.
- `deploy/docker-compose-local.yml` — на хосте заняты `8000` и `5432`:
  - `api-gateway`: `8080:8000`, `db`: `5433:5432`; `NUXT_PUBLIC_API_BASE` в `.env` фронта → `http://localhost:8080`.
  - **Важно:** для `api-gateway` нужен `ports: !override`. Без него compose **склеивает** списки портов с базовым файлом, `8000:8000` остаётся и контейнер падает на занятом порту.
- Запуск: `docker compose -f docker-compose.yml -f docker-compose-local.yml up -d --build` из `deploy/`. Для вёрстки удобнее погасить контейнер `web` и запускать фронт через `npm run dev` в `src/web/` (hot-reload).

## 2026-09-18 — Подключение чатов к API и поиск пользователей

После того как Артём добавил `POST /users/search` в `identity`, экран чатов подключён к реальному бэкенду — переписываться можно прямо в интерфейсе. Экран теперь живёт в `components/ChatsScreen.vue` (Артём вынес его из `index.vue` под модалку настроек), изменения внесены туда.

- **`app/composables/useChats.ts`** — все запросы чатов, по образцу `useAuth`:
  - `loadChats()` — `GET /chats` → по каждому чату `GET /chats/{id}/members` → имена собеседников через `GET /users?ids=`. Чат с самим собой поддержан (единственный участник — я).
  - `loadMessages()` / `loadOlderMessages()` — история по 50 сообщений, курсор `before_msg_id`; бэкенд отдаёт новые→старые, в ленте разворачиваем.
  - `sendMessage()` — `POST /chats/{id}/messages` с `client_msg_id: crypto.randomUUID()` (идемпотентность).
  - `searchUsers()` — `POST /users/search { tag, limit: 20 }`, ведущий `@` срезается, себя из выдачи убираем, ответы на устаревшие запросы отбрасываются.
  - `openChatWith()` — `POST /chats/direct`; если чат с человеком уже есть, бэкенд возвращает его — дублей нет.
- **`app/stores/chat.ts`** — локальная «отправка» убрана; чаты сортируются по последнему сообщению (бэкенд отдаёт без сортировки), новое сообщение поднимает чат наверх; добавлены пагинация (`hasMoreByChatId`), состояния загрузки/ошибки, результаты поиска людей.
- **`components/chat/Sidebar.vue`** — поле «Поиск по @username» одновременно фильтрует свои чаты (блок «Чаты») и ищет людей на сервере (блок «Люди», запрос через 300 мс после последней буквы). Вернулась иконка ✏ «Новый чат» — ставит фокус в поиск. Состояния «Загрузка…», «Ищем…», «Никого не нашли», ошибки.
- **`components/chat/UserItem.vue`** — новая строка найденного пользователя: аватар с инициалами, имя, `@username`.
- **`components/chat/Dialog.vue`** — отправка через сервер: кнопка блокируется на время запроса, при ошибке показывается текст, черновик не стирается. Подгрузка старых сообщений при прокрутке вверх с сохранением позиции.
- **`components/chat/Empty.vue`** — вернулась кнопка «▶ Новый чат» (фокус в поиск).
- **`components/ChatsScreen.vue`** — загрузка чатов при входе (стор сбрасывается, чтобы не остались данные прошлого пользователя), загрузка истории при выборе чата.

## 2026-09-19 — Сообщения в реальном времени (WebSocket)

Новые сообщения приходят сразу, без перезагрузки страницы. Бэкенд (`ws-gateway`) был готов, работа только на фронте.

- **`app/composables/useWs.ts`** — обработка входящих событий (`onMessage`), автоматическое переподключение при обрыве (паузы 1с → 2с → 4с… до 15с), `onReconnect` после восстановления связи. Метод `send()` помечен комментарием: ws-gateway игнорирует сообщения от клиента, отправка только через REST.
- **`app/composables/useChats.ts`**:
  - `handleRealtimeEvent()` — разбирает `message.created`; id в событии называется **`message_id`**, а не `id`, как в REST. Своё сообщение приходит эхом и отсеивается по id. Если пишет человек, чата с которым ещё нет в списке, — список перезагружается.
  - `resync()` — после переподключения перечитывает чаты и открытую переписку, чтобы не потерять пришедшее во время обрыва.
  - Имена собеседников снова одним запросом `GET /users?ids=…&ids=…` — Артём починил потерю повторяющихся параметров в `api-gateway`, обход по одному id убран.
- **`app/types/chat.ts`** — тип события `MessageCreatedEvent`.
- **`components/ChatsScreen.vue`** — сокет подключается при входе и закрывается при выходе из аккаунта.

**Исправлен старый баг адреса сокета:** в `.env.example` и `nuxt.config.ts` с первого дня стояло `ws://localhost:4333` — без пути `/ws`. ws-gateway слушает только `/ws`, на корень отвечает `404`, поэтому соединение не открывалось и фронт молча переподключался по кругу. До подключения вебсокета ошибку никто не замечал — сокет не использовался. Через nginx (`/ws`) баг не проявлялся. Исправлено на `ws://localhost:4333/ws`.

> Кто запускает фронт через `npm run dev`: допишите `/ws` в свой `src/web/.env` — `.env` не в гите и сам не обновится.

## 2026-10-29 — Аудио в переписке

- **`components/chat/AudioPlayer.vue`** — свой плеер прямо в пузыре: круглая кнопка «слушать / пауза», волна из 48 столбиков с подсветкой прослушанного, клик по волне — перемотка (с клавиатуры — стрелки по 5 с), время, имя файла, кнопка «Скачать».
  - Волна строится по самому файлу (Web Audio, пики громкости), кэшируется по id; для файлов больше 25 МБ и при ошибке декодирования вместо волны тонкая полоска прогресса.
  - Одновременно играет только одно аудио: запуск другого ставит предыдущее на паузу.
  - Свои сообщения — тёмная кнопка и волна на амбере, чужие — амбер на синем.
- **`components/chat/Attachment.vue`** — файлы `audio/*` показываются плеером; при истёкшей ссылке берётся новая, как у видео.
- **`components/chat/Message.vue`** — в сообщении только с аудио время с галочками не перекрывает подпись плеера.
